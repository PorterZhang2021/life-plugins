# 每日时间块日记管理

## 日记文件结构

日记文件位于 `M/每日日记/YY年/M月/D.md`，例如 `M/每日日记/26年/5月/5.23.md`。

文件顶部加**日期类型标记**：
- `#workday` — 周一到周五，Todo **不写时长**（工作事项不按小时计）
- `#weekend` — 周日，Todo **写时长**（学习/个人项目需要预估时间）

```markdown
#weekend

## 可能的 Todo
- [任务1] - [时长]
- [任务2] - [时长]
- ...

## 完成总结
- [大类A]
  - [子项1] - [累计时长]
- [大类B]
  - [子项1] - [累计时长]

[开始时间] 开始
主要目标：
- [具体任务] - [预计时长]
实际目标：
- [实际完成情况描述]
[结束时间] 结束
```

每个日记由多个**时间块**组成，块之间用空行分隔。


## 前置检查

每次用户要求操作日记时，先执行以下检查：

1. **判断日期类型**（根据当天星期几）：
   - 周一到周五 → `#workday`
   - 周日 → `#weekend`
2. **定位当天日记文件**：`M/每日日记/YY年/M月/D.md`（根据当前日期）
   - 例如 2026 年 5 月 23 日 → `M/每日日记/26年/5月/5.23.md`
   - **忽略废弃的旧格式文件**（如 `5月6日.md`、`5月11日.md` 等）
3. **检查文件是否存在**：
   - **不存在**：
     - 创建当天的日记文件（自动创建 `YY年/M月/` 目录）
     - 文件第一行写入日期类型标记（`#workday` 或 `#weekend`）
     - 调用 `scripts/carry_over_todos.py` 搜索历史同类型日记，提取未完成的 Todo
     - 将汇总的 Todo 作为初始 Todo 写入文件
   - **存在**：读取文件内容，继续下一步
4. **检查文件中是否已有"可能的 Todo"段落**：
   - **没有 Todo**：告知用户"还没有今天的 Todo，请先列出今天要做的事情"，引导用户列出后创建首个时间块
   - **已有 Todo**：正常执行创建新时间块或补充闭环的操作

> 关键原则：**没有当天日记文件或没有 Todo，都不能创建时间块**。

> **workday / weekend 分离原则**：工作日和周日的 Todo 互不干扰。周日没做完的事顺延到下个周日，工作日没做完的事顺延到下个工作日。

## 操作规则

### 整体流程

日记文件结构：

**全局 Todo 清单**（文件开头，唯一一份）：

`#weekend` 示例（写时长）：
```markdown
#weekend

## 可能的 Todo
- 计算机概念学习 - 3 小时
- 英语对话练习 - 2 小时
- ...
```

`#workday` 示例（不写时长）：
```markdown
#workday

## 可能的 Todo
- 修复 push gateway 问题
- 工作流支持脚本任务
- ...
```

**时间块**（只包含目标与闭环，不写 Todo）：
```markdown
[时间] 开始
主要目标：
- [任务] - [预计时长]
实际目标：
- [实际完成情况]
[时间] 结束
```

**顺序**：先列全局 Todo → 用户说"创建时间块" → 从全局 Todo 中选主要目标 → 执行 → 闭环 → 更新全局 Todo

### 1. 创建新日记文件（仅全局 Todo 清单）

当用户开始新的一天：

1. **整理昨天日记**：读取昨天的日记文件，提取所有时间块的"实际目标"，**合并相似项并累加时间**，用**子层级**归类后写在"## 可能的 Todo"下面：
   ```
   ## 可能的 Todo
   - [未完成的任务]
   
   ## 完成总结
   - [大类A]
     - [子项1] - [累计时长]
     - [子项2] - [累计时长]
   - [大类B]
     - [子项1] - [累计时长]
   - ...
   ```
   
   **归类原则**：按项目/主题分大类，具体完成内容作为子项。例如：
   ```
   - timer 项目
     - 创建 timer 功能完成
     - 开启 timer 功能完成
     - 生成 task 的任务规划
   - push gateway
     - 功能问题修复
     - 携带的问题查看
   ```
2. 确定日期类型标记（`#workday` 或 `#weekend`）
3. 调用 `scripts/carry_over_todos.py` 搜索历史同类型日记，提取未完成的 Todo
4. 创建日记文件，写入标记 + 全局"可能的 Todo"清单
5. **不自动创建时间块**，等待用户说"创建时间块"

如果用户还有额外的 Todo 要添加，先补充到全局 Todo 清单中。

> 每天晚上用户也可能主动问"今天完成了什么"，此时同样提取当天所有实际目标，汇总为"完成总结"写在 `## 可能的 Todo` 下面。

### 2. 创建时间块

当用户说"创建时间块"并指定主要目标时：

1. 获取当前系统时间作为**开始时间**
2. 将用户指定的**主要目标**写入 `- [任务] - [预计时长]`
   - **默认时长为 1 小时**（用户一般按 1 小时一个时间块）
   - 如果用户明确说了时长，按用户说的写
   - 主要目标从文件开头的全局 Todo 中选取，或用户新增
3. 在文件末尾追加完整时间块（**不包含"可能的 Todo"**）

> 用户也可能直接说"开始下一个任务"或"继续"，此时引导用户指定主要目标，或从全局 Todo 中建议一个。

### 3. 闭环后更新全局 Todo

当用户表示"完成了"某段任务、补充实际目标和结束时间后：

**周末（`#weekend`）**：
1. **更新 `## 可能的 Todo`**：
   - 计算剩余时间 = 原时长 - 实际完成时长
   - 剩余时间 = 0：从 Todo 中**移除**
   - 剩余时间 > 0：更新为剩余时间，保留追溯格式 `（原 X 小时，已完成 Y 小时）`
2. **更新 `## 完成总结`**：
   - 在对应大类下增加子项，写上实际完成时长
   - 如：`计算机概念学习 - 1 小时`

**工作日（`#workday`）**：
1. **更新 `## 可能的 Todo`**：
   - 任务已完成：直接从 Todo 中**移除**（workday 不写时长）
2. **更新 `## 完成总结`**：
   - 在对应大类下增加子项（不写时长）
   - 如：`修复 push gateway 问题`

**时间计算逻辑**：剩余时间 = 原预计时间 - 已完成时间。例如原 3 小时完成 1 小时，剩余 2 小时。

### 脚本辅助

**`scripts/extract_last_block.py`** — 提取日记最后一段时间块的结构化信息：

```bash
python scripts/extract_last_block.py "M/每日日记/26年/5月/5.24.md"
```

输出 JSON 包含：
- `start_time` / `end_time` — 开始/结束时间
- `main_goal` — 主要目标（任务 + 时长）
- `actual_goal` — 实际目标内容
- `is_closed` — 是否已闭环（有实际目标和结束时间）

**何时调用**：每次需要操作日记时，先调用此脚本获取最后一段的完整信息，避免 Kimi 手动读文件后误判段落边界。

**`scripts/carry_over_todos.py`** — 从历史同类型日记的文件开头全局 Todo 清单中提取未完成的 Todo：

```bash
python scripts/carry_over_todos.py "M/每日日记/" weekend
```

输出 JSON 包含：
- `found` — 找到的 Todo 数量
- `todos` — Todo 列表（每项含 `text`、`duration`、`note`、`source`）

**何时调用**：创建新日记文件时，调用此脚本搜索同类型（workday/weekend）的历史日记，从文件开头的 `## 可能的 Todo` 中提取未完成的任务，作为新日记的初始 Todo 列表。

### 4. 补充实际目标与结束（闭环）

当用户表示"完成了"某段任务时：

1. 在**当前时间块末尾**（紧跟主要目标，不空行）添加：
   ```
   实际目标：
   - [实际完成内容]
   [当前时间] 结束
   ```
2. 获取当前系统时间作为**结束时间**
3. **更新文件开头的全局 Todo 清单**（见上方"闭环后更新全局 Todo"）
4. 格式与第一段保持完全一致

### 5. 关键格式约束

- **段落连续性**：`实际目标` 和 `结束时间` 紧跟在 `主要目标` 后面，**不插入空行**
- **块间分隔**：不同时间块之间用**一个空行**分隔
- **时间格式**：与用户的口语习惯保持一致（如 "08点 16"、"11点 00"）
- **避免错位**：确保实际目标和结束时间写在**当前正在操作的时间段**末尾，不要插入到其他时间段中

### 6. 防止错位（极其重要）

**问题**：日记文件中可能出现多个相同的"主要目标"文本，直接用 StrReplaceFile 匹配会命中第一个，导致内容插入到错误的时间块。

**解决方案**：补充实际目标时，必须先用 ReadFile 读取文件最后几行，确认最后一段的**完整上下文**，然后使用**包含唯一上下文的字符串**进行替换。

**正确做法**：
1. 先用 `ReadFile` 读取文件末尾，确认最后一段的内容
2. 替换时使用**主要目标 + 开始时间**作为 old string，确保唯一匹配到最后一段

**错误示例**（会匹配到第一个）：
```
old: "主要目标：\n- 进行一小时计算机概念内容学习 - 1 小时"
```

**正确示例**（包含唯一上下文）：
```
old: "20点 01 开始\n主要目标：\n- 进行两小时深度对话练习 - 2 小时"
```

## 示例

```markdown
#weekend

## 可能的 Todo
- 线性代数内容学习 - 2 小时
- 计算机概念内容学习 - 3 小时
- 专栏文章内容的修改与发布 - 2 小时
- 2小时的深度对话练习
- Agent 编排相关项目功能学习 - 6 小时

## 完成总结
- 线性代数
  - 内容学习 - 2 小时
- 计算机概念
  - 内容学习 - 3 小时
- 专栏文章
  - 内容的修改与发布 - 2 小时
- 深度对话
  - 练习 - 1 小时

07:04 开始
主要目标：
- 进行一小时的线性代数内容学习 - 1 小时
实际目标：
- 进行了一个小时左右的线性代数内容学习
08点 16 结束

8 点 41 开始
主要目标：
- 进行一小时计算机概念学习 - 1 小时
实际目标：
- 进行了一小时左右的计算机概念内容学习
09点 49 结束
```
